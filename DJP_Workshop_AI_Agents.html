    For IT admins: how memory is governed

    Where memories live

    Saved memories, details from chat history and custom instructions are stored in a hidden folder in the user’s Exchange mailbox, under the same security and compliance policies as other mailbox data.

    On by default

    Memory depends on the Enhanced personalization control, which is on by default. Turn it off for the tenant or a group of users; users then can’t turn on custom instructions, saved memories or chat history.

    User control

    Saved memories stay until the user deletes them in Settings › Personalization. Deleting a chat doesn’t delete memories saved from it.

    eDiscovery

    Admins can search and delete saved and inferred memories with Purview eDiscovery (item class IPM.Contact, CopilotMemory folder). Custom instructions aren’t discoverable yet.

    Retention & audit gaps

    Purview retention policies don’t apply to memory, memory actions aren’t in the audit log, and admins can’t restrict what goes into memory.

    Licence & status

    Preview. Available to Copilot Chat users with and without a Microsoft Copilot licence. Check Settings › Personalization in your tenant.

    Anatomy of an agent

    Select a part.

    1 · Instructions

    Role, scope, numbered steps, output format and what the agent must never do. Treat them like a runbook.

    In today’s workshop: Lab 1: the template you use to build your own agent.

    2 · Knowledge

    Public websites, SharePoint, files and data the agent answers from, always within the user's own permissions.

    In today’s workshop: An IT SOP library the agent cites when it answers “how do I…” questions.

    3 · Tools

    How the agent acts: connectors, agent flows, REST APIs, MCP servers and computer use.

    In today’s workshop: Copilot Studio demo: Send an email (V2) sends the confirmed request summary.

    4 · Triggers

    Events or schedules that start the agent without a prompt: a new email, a new list item, a time of day.

    In today’s workshop: Live demo: a request email arriving in the IT shared mailbox.

    5 · Orchestration

    The agent reasons about which tool or knowledge to use next. Flows and topics keep critical steps deterministic.

    In today’s workshop: Copilot Studio demo activity map: the agent asks a question, confirms, then calls the tool.

    Guardrails wrap every part: least-privilege access, human approval for high-impact actions, clear “don’t act” boundaries, audit logging and monitoring.

    Module 3 · need 02

    Automating work processes

    Agent flows give you predictable, rule-based automation with AI steps and human approvals inside. Agents decide when to call them.

    Trigger

    Manual, scheduled, an event such as a new email or list item, or called by an agent

    →
    AI actions

    Run a prompt, process a document, call an agent

    →
    Human in the loop

    Approval request, or ask a person for information

    →
    Connectors & logic

    Microsoft 365, other services, custom connectors; loops and conditions

    Use a flow or topic when…

    • Steps must run in a fixed order
    • Rules are compliance- or policy-driven
    • Actions are high-impact or irreversible

    Let the agent orchestrate when…

    • Requests vary and need reasoning
    • The agent must pick the right tool or knowledge
    • Mistakes are low-impact and easy to correct

    Autonomous agents need guardrails by design

    Narrow scope

    One well-defined task; say where its authority ends.

    Least privilege

    Only the permissions it needs; read-only where possible.

    Validate triggers

    Check sender, keywords or source so a trigger can't be spoofed.

    Human approval

    People approve sensitive actions; AI approvals can take routine yes/no with people on exceptions.

    Audit & monitor

    Log triggers, decisions and actions; alert on unusual behaviour.

    Roll out gradually

    Sandbox, then a pilot group, then expand autonomy step by step.

# Laporan Layanan TI Mingguan (standar DJP)

## Kapan digunakan
Gunakan skill ini saat pengguna melampirkan ekspor tiket (CSV) dan meminta laporan mingguan, ringkasan SLA, atau review layanan. Jangan gunakan untuk satu tiket saja.

## Langkah
1. Periksa apakah file memiliki semua kolom di `reference/columns.md`. Jika ada kolom yang kurang, sebutkan kolom tersebut lalu berhenti.
2. Gunakan periode yang disebutkan pengguna. Jika tidak disebutkan, gunakan 7 hari terakhir di file (default script).
3. Jalankan `scripts/kpi.py <file> [--from YYYY-MM-DD --to YYYY-MM-DD]`. Gunakan angkanya persis. Jangan menghitung ulang KPI secara manual.
4. Isi `templates/report-template.md` dengan output script. Pertahankan nomor laporan, urutan bagian, dan judulnya.
5. Tulis ringkasan dan tiga rekomendasi dalam Bahasa Indonesia yang formal dan ringkas. Rekomendasi pertama harus menanggapi status IKL.
6. Isi "Catatan data" dengan nama file, periode, jumlah baris, jumlah tiket unik, dan SEMUA masalah data yang dilaporkan script.

## Aturan standar DJP
- Pelanggaran SLA dihitung ulang: ResolutionHours > SLA_Hours. Kolom SLA_Breached hanya pembanding; ketidaksesuaian dilaporkan sebagai masalah data.
- Baris dengan TicketID ganda dihapus (baris pertama dipertahankan) dan dilaporkan.
- Indeks Kesehatan Layanan (IKL) = 100 − 1,5 × tingkat pelanggaran SLA keseluruhan (%) − 3 × jumlah tiket P1/P2 yang masih terbuka; batas 0–100. Status: ≥ 80 Hijau (Sehat), 60–79,9 Kuning (Perlu perhatian), < 60 Merah (Kritis).
- Nomor laporan: LTI-MGG-<tahun ISO>-W<minggu ISO akhir periode>.
- Tandai MERAH prioritas dengan tingkat pelanggaran SLA di atas 20%.
- Gunakan hanya data di file. Jangan pernah mengarang angka, unit, atau penyebab.
- Jangan pernah mencantumkan nama pelapor atau data pribadi. Laporkan per unit dan kategori saja.
- Jika periode berisi kurang dari 10 tiket, sampaikan bahwa angkanya belum dapat diandalkan untuk melihat tren.

    Copilot Cowork: from answers to finished work

    1Describe

    Say what you need in plain language, with files from OneDrive or SharePoint.

    2Plan

    Cowork breaks the request into steps and the tools it will use.

    3Act

    It drafts documents, builds spreadsheets, prepares emails and meetings.

    4Approve

    Sensitive actions — send, post, change a shared system — wait for your approval.

    5Deliver

    Results land in your OneDrive; repeat work becomes an automation.

    You stay in control
    Approve actions

    A preview and risk level for medium and high-risk actions; approve once, for the session, or cancel.

    Pause, resume, cancel

    Stop or redirect a task at any time.

    Your permissions only

    Every task, including automations, sees only the data you can see.

    Automations

    Scheduled prompts and event-driven tasks on a new email or Teams message; draft-and-approve by default.

    Good to know
    • Works with OneDrive and SharePoint files, not files on your device
    • Can’t delete files or folders
    • Attached files must be under 200 MB
    • Can’t read encrypted files

    Works in the browser at copilot.cloud.microsoft, in Outlook and Teams, and in the Copilot desktop and mobile apps.

    Cowork for IT: access, cost and governance

    Access

    Microsoft 365 Copilot licence plus usage-based billing. Grant Cowork through a spending policy scoped to a security group in Microsoft 365 admin center › Copilot › Cost management.

    Cost control

    Per-user or per-group limits; usage in the admin center and the Cowork usage report; estimate first with the Cowork cost estimator.

    Discoverability

    Admins decide whether users see Cowork; users can request access, and admins approve by policy, cost and compliance.

    Extensions & models

    Admins control which plugins (skills and connectors) are available, and can turn off individual models, such as Anthropic models.

    Data protection

    Files are processed in a temporary, isolated environment inside the Microsoft 365 service boundary; data residency follows Copilot.

    Audit & compliance

    Cowork activity, including automated tasks, is in the unified audit log; Microsoft Purview policies apply.

    Module 7 · run agents safely

    Governance controls for agents

    Data policies

    Block connectors, HTTP requests, channels or event triggers per environment; require user authentication.

    Credential control

    Allow only end-user credentials for tools, per environment or group.

    Security scan

    Makers see warnings before publishing risky settings: no authentication, maker credentials, org-wide sharing.

    Environments

    Route makers to a safe development environment; gated release to production.

    Audit & monitoring

    Maker and agent activity in Microsoft Purview audit; alerts through Microsoft Sentinel.

    Agent lifecycle

    Enable, block or remove agents for users in the Microsoft 365 admin center.

    Questions DJP should settle first

    To validate with DJP legal, security, system and data owners. These are questions, not legal advice.

    1

    Which data classes, such as taxpayer data under confidentiality obligations, must never reach an agent, and how is that enforced?

    2

    Do government rules on electronic systems and data location (e.g. PP 71/2019, SPBE) set conditions for cloud agents?

    3

    How does UU PDP apply to prompts, agent knowledge and data that agents read from DJP systems?

    4

    Which DJP systems may agents read from, and which may they write to?

    5

    Who approves a new agent, its connectors and its identity before it goes live?

    6

    What credit budget, user group and review cadence applies to a pilot?

    Source: Microsoft Learn — Configure data policies for agents; Control maker-provided credentials; Automatic security scan; Secure your Copilot Studio projects; Key concepts: security and governance

    Wrap-up

    Quick knowledge check

    Select a question to reveal the answer.

    1You need a careful root-cause analysis in Copilot Chat. Which mode should you pick?

    Think deeper, in the model selector.

    2Which agent part lets an agent act on DJP systems?

    Tools: connectors, agent flows, REST APIs, MCP servers and computer use.

    3When should a process use a flow or topic instead of free agent reasoning?

    When steps must run in order, are policy-driven, or are high-impact or irreversible.

    4A system has no API. What can the agent use, and what does it cost?

    Computer use: 5 Copilot Credits per step (15 with a premium model).

    5Whose permissions does an agent use for tools by default?

    The end user's credentials.

    6Which agents can DJP use today at no extra cost?

    Agent Builder agents with instructions, public websites, code interpreter and image generator.

    7Which four ingredients make an effective prompt?

    Goal, context, source and expectations.

    8What does Microsoft 365 Copilot (Premium) add on top of Copilot Chat (Basic)?

    Work IQ grounding in your emails, files, meetings and chats; Copilot inside the Microsoft 365 apps; Researcher and Analyst.

    9Before Cowork sends an email or posts a Teams message, what happens by default?

    It asks for your approval; automations are draft-and-approve by default.

    10What does Cowork need besides a Microsoft 365 Copilot licence?

    Usage-based billing (Copilot Credits), granted through a spending policy.
